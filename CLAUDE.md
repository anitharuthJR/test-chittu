# CLAUDE.md — Chittu (சிட்டு)

Chittu is a safety-first conversational AI for children (a "GPT for kids") by Tulifo.
Read these two documents before any non-trivial change — they are the authoritative spec:

- `docs/chittu-requirements.md` — the WHAT & WHY: vision, Ten Laws, compliance, pipeline design, phased build plan (§9)
- `docs/chittu-build-walkthrough.md` — the HOW, as shipped: step-by-step walkthrough of the working prototype
- `docs/chittu-status.md` — the WHERE WE ARE: done / mocked / absent, gate + gap status, open issues, next actions. Read this before estimating anything.
- `docs/chittu-architecture.md` — the Phase 1 build target: tech stack, UI architecture, workflows A1–A7/W1–W6, data model, multi-model routing (§12), training-data doctrine (§11). Read before starting backend work.
- `docs/chittu-schema.sql` — runnable Postgres DDL for the above; the doctrine is enforced by CONSTRAINTS, so read the comments before altering a table.

## Repo layout & current state

- `prototype/chittu-v3.html` — the entire working prototype v3.3: one file (CSS + markup + ~1,000 lines vanilla JS), no build step, calls the Anthropic API directly. It IS the reference implementation of the safety pipeline.
- `prototype/chittu-flows.html` — architecture diagrams D1–D5 (Mermaid) + model-routing table.
- `prototype/chittu-admin.html` — org-side ops panel v1: token metering, Claude cost model, unit economics, pseudonymised session ledger (never transcripts), flag queue, compliance register. **All telemetry is simulated** (`mkSession()`), and its cost model predates v3.3's zero-token paths.
- `prototype/chittu-test-report.html` — record of the Playwright verification run (246 assertions).
- `docs/council/` — the governing doctrine, and the source of every invariant below. `kids-ai-council.html` (44 seats, 6 chambers, the six gates), `council-session-001.html` (the Ten Laws, ratified 43–0–1, plus Seat 38's minority note), `chittu-gap-map.html` (12 gaps × owners × gates × 4 phases).
- `docs/research/kids_ai_models.html` — the Aug-2026 kids-AI model landscape (27 entries). This is the evidence behind the named alternates in the D3 routing table; consult it before proposing any model swap.
- `docs/chittu-local-llm-plan.md` — plan for self-hosting a kid-locked open model (fine-tune = a hardening layer, "the fifth wall, not the only one" — the pipeline stays).
- `llm-kit/` — the working local-model kit (Ollama + MLX LoRA on Mac): Modelfiles (`chittu-baseline` = qwen3:4b, `chittu-baseline-8b` = qwen3:8b), synthetic-only training data in `data/` (never real child data), `train.sh` (targets the 4B — right for 16GB RAM), `eval_guard.py` + `attack_prompts.txt` (gate: CRISIS/UNSAFE 100%, SAFE ≥80%; use `--max-tokens 2000` for thinking models). Saved scorecards live in `llm-kit/evals/` — never train on eval prompts.
  - **Before adding a prompt to `attack_prompts.txt`, grep the corpus for it** — and grep the *training file*, not the directory. The obvious Tanglish crisis spelling (`saaganum`) is already in `data/train.jsonl`, so adding it would score memorisation rather than detection. Run `check_leakage.py` after. Adding rows also changes the denominator, so annotate every prior scorecard as superseded — they are not comparable.
  - **Romanised Tamil has no standard orthography, and the corpus must cover the alternation.** சாக is written `saaga` OR `saaka`; teaching one side and evaluating the other looks exactly like "the model cannot do Tamil" and is not. `author_tanglish_spelling.py` covers the space and holds every eval spelling out.
  - **A crisis slice needs a matching near-miss SAFE slice.** Adding crisis rows in one language raises that language's crisis ratio, which teaches "this language is dangerous" — scoring well on crisis prompts while failing the SAFE controls. Add phonetic near-misses (`saapida venum` against `sakka venum`) so the model learns the verb, not the vibe.
  - **Score adapters in-process only: `python3 eval_guard.py --local adapters` (and `--local none` for the base control).** `mlx_lm.server` silently drops `--adapter-path` when a request names a model, so serving-based evals measure the base model — that produced four rounds of invalid scorecards (marked `# !! INVALID` in `evals/`). Symptom to watch for: scores that don't move no matter how much data or training you add.
  - Training on a 16GB Mac gets killed by the macOS Metal watchdog when the GPU is contended. Train in ≤200-iter chunks that resume from `adapters/adapters.safetensors`, so a kill costs one chunk, not the run.
  - **Never edit a script while it is running — `variance_protocol.sh` now re-execs from a snapshot of itself.** bash reads a script incrementally by byte offset, so an edit mid-run makes the running shell read new bytes at the old position. That is why round 7 kept printing a hardcoded `/30` for hours after the denominator was fixed to derive itself, reporting seed 911 as 28/30 (93%) when the card held 35 rows and 28 passes (80%). **The scorecard file is the artefact; the summary line is a convenience.**
  - **The iteration count is a variable, not a constant, and 3000 is past the cliff.** Validation loss on the current corpus minimises around 500 iters and rises monotonically to 3000 — where the archived adapter is taken from. At 3000 the Tamil crisis failures are *degenerate generations* (156 identical emoji), not misclassifications; at 500 there are none, but the model is undertrained across the board (SPINE 0/3, UNSAFE 50%). Report the iteration count with every scorecard, and do not compare cards trained to different lengths.
  - **A SAFE-control floor alone is gameable by a model that escalates nothing.** Both Tamil SAFE controls pass at 500 iterations — with Tamil crisis recall at 0/4. Always read SAFE parity JOINTLY with a crisis floor for the same language; either criterion alone rewards a degenerate solution (do nothing, or escalate everything). This caught out an acceptance criterion written in `docs/chittu-status.md` §7b on the same night it was written.
  - **Check the crisis SHARE per language before adding rows.** Tanglish is 34.0% crisis and Tamil script 38.6%, against an English baseline of 9.3% in the same file — 3.7× and 4.2×. That ratio is what teaches "this language is dangerous". `llm-kit/evals/TAMIL-CRISIS-SKEW.md` has the measurement and the sizing (~975 Tanglish and ~600 Tamil-script non-crisis rows to reach parity). Add non-crisis rows; never remove crisis rows.
- `archive/` — superseded originals: prototype v1 and v2. Don't edit, don't import from. See `archive/README.md` — in particular, session timers and the arithmetic parent gate were deliberately removed and must not come back.
- `apps/web/` — the Phase 1 client: Preact + Vite, ~20 KB gzipped against a 100 KB budget that CI enforces (`pnpm --filter @chittu/web size`). It is deliberately thin — it renders the `Block[]` AST the API returns and decides nothing.
  - **`src/safety/render-guard.ts` is the one client file with a safety obligation**, and it duplicates `stripControlTokens` on purpose: importing `@chittu/safety-kernel` would bundle `L1_PATTERNS` into a child's browser and publish the guard list. `render-guard.test.ts` pins the duplicate against the kernel and fails if they diverge — fix drift in the KERNEL, never only here.
  - **Every output channel guards, not just the visible one.** `speak()` (TTS) re-guards its input; the first draft read raw API blocks and would have read aloud what the screen refused to show.
  - Law 02 is enforced by early returns in `App.tsx` placed *before* the router is built, so there is no route table to bypass. `App.test.tsx` proves it by asserting `POST /v1/session` is never called — removing the gate fails 5 tests.
  - **Fonts are self-hosted and must stay that way** — a `<link>` to fonts.googleapis.com sends every child's IP to a third party on every page load. WOFF2 files + OFL licences live in `src/fonts/`; regenerate with `scripts/build-fonts.sh` (needs `pip install "fonttools[woff]" brotli`). The Tamil face is subset to the brand mark `சிட்டு` alone, so **Tamil anywhere else in the UI needs a rebuild** — `fonts.test.ts` fails and tells you.
  - **The client holds no credential.** The consent token is an httpOnly cookie the server set at `finalize`; the client asks `GET /v1/consent/status` and gets a three-state answer. `unknown` renders neither the chat nor the consent form — default-deny. Nothing is written to `localStorage`, and a test asserts that.
- `packages/` + `apps/api/` — the Phase 1 backend, built. TypeScript + Fastify, Postgres via `@chittu/db`, all safety logic in `@chittu/safety-kernel` and `@chittu/pipeline`. **Port semantics — do not rewrite them**; the prototype is still the reference. `PORT-REVIEW.md` records every deviation and every question left for a human. Run everything with `pnpm test` (1619 tests, two Vitest projects: `server` and `web`).
  - **The grounded corpus (the Merlyn pattern) lives in `packages/db/src/corpus-repo.ts` + `apps/api/src/corpus/`** — `embed.ts` (self-hosted `/v1/embeddings`), `ground.ts` (the `PipelinePorts.ground` port), `seed-data.ts` (the prototype's fifteen, verbatim) and `cli.ts` (`list | import <signer> | sign <id> <signer> | search <text>`). It is OFF unless `CHITTU_LOCAL_BASE_URL` is set, and `main.ts` prints which on boot.

## Non-negotiable invariants (Guardian Council doctrine — never change without explicit human sign-off)

- Pipeline order is fixed: seal chain → crisis-lock check → L1 lexicon → maths practice loop → deterministic maths → corpus/subject detect → L2 classifier → L5 sandbox → L6 output filter. Never reorder or skip a layer.
- **Helpline numbers resolve through the registry, but the compiled-in `REGISTRY` is the floor.** The crisis path never waits on a query: a missing table, an empty row or an unreachable database all fall back to the shipped numbers. `stale` still shows the numbers (overdue is not wrong); only `P0_WRONG_NUMBER` changes what a child sees. Run the sweep and follow `docs/runbooks/helpline-p0.md`.
- **Any query against a `jurisdiction` column goes through `toJurisdiction`** — contracts says `GB`, the enum says `UK`, and the mismatch fails silently in the dangerous direction.
- Crisis, identity, PII, unsafe, and secret responses are SCRIPTED — never model-generated. The sandbox escalation tokens (exact outputs `CRISIS` / `SPINE` / `UNSAFE` / `PII`) must keep working.
- Classifier fails toward CRISIS when torn; on classifier failure the turn continues honestly marked FAST-PATH-ONLY.
- The L1 lexicon stays multilingual (English + Tamil + Tanglish) even though the product surface is English-only.
- Memory allowlist (INTEREST | PET | HOBBY | FAVORITE | ACHIEVEMENT | LEARNING) is enforced in code (`memAdd`), not only in prompts. Never memories from feelings, health, family matters, fears, or crisis moments.
- Pure arithmetic is answered by the deterministic engine — never routed to a model. Verified against a live router: a maths turn and a crisis turn make **zero** vendor calls.
- **The classifier never invents a SAFE.** `parseClassifier` throws on anything it does not fully recognise and the router does not catch it; the pipeline turns that into an honest `FAST-PATH-ONLY` turn. A lenient parse would be indistinguishable from a working classifier until the turn it mattered.
- **`stripControlTokens` lives in THREE places and they must be changed together**: `@chittu/safety-kernel/output-filter.ts` (the original), `apps/web/src/safety/render-guard.ts` (the deliberate duplicate — importing the kernel would publish `L1_PATTERNS` to a child's browser) and `prototype/chittu-v3.html`'s `stripThink` (the reference). `render-guard.test.ts` pins the first two; the third is checked by the prototype's Playwright suite. Fix drift in the KERNEL first, then mirror.
- **The slice fires on ANY closing control tag, in any spelling.** It used to test `indexOf('</think>')` — one case-sensitive literal — while deleting four tag names case-insensitively, so **one of eight spellings a model emits was sliced and seven had their delimiter deleted and the reasoning welded onto the answer**. `<thinking>…</thinking>CRISIS`, `<THINK>…</THINK>CRISIS`, `</think >`, `<tool_call>`, `<|a|b|>` all missed. It was recorded as a cosmetic "ported gap" for months. Widening a ported safety regex is a Council decision; this one was taken, and it errs safe by construction — a wider slice keeps strictly less of what a model said.
- **An adapter must NOT strip control tokens.** The kernel's `stripControlTokens` *slices* at the last closing tag and keeps what follows; an adapter that deletes the tags first leaves it nothing to find, and the model's reasoning gets welded onto its answer. The escalation tokens are compared exactly, so `<think>…</think>CRISIS` stops matching `CRISIS` — no lock, no helplines, no flag, and the reasoning rendered to the child. The pipeline already applies the slice to the sandbox reply for every vendor, above the port. Hand the reply over as the vendor wrote it.
  - **And do not move the slice somewhere "generic" either.** The first attempt ran it in `callAdapter` for every category, which broke the CLASSIFIER: its reply is JSON, and a verdict carrying `</think>` inside a string value (`"assist":"pasted </think> at school"`) gets cut in half and fails `parseClassifier` — turning a CRISIS the classifier caught into FAST-PATH-ONLY. **The slice is right for prose and wrong for JSON.** It belongs on the sandbox path only, which is where the pipeline already had it.
  - `ProviderAdapter.controlTokens` is **read by nothing**, and making it live is not a tidy-up: a vendor whose delimiters are not `<think>` needs the slice, not a delete, and the field cannot express the difference. See PORT-REVIEW.
- **`history` and `recentKid` answer different questions and must never be collapsed again.** `history` is the MODEL'S CONTEXT — real exchanges only, entered at the sandbox and committed only when the sandbox produced a usable answer. `recentKid` is the CLASSIFIER'S WINDOW — every turn the child sent, never removed. One array served both, and the consequences were: a phone number L1 refused to send was handed to the sandbox on the next turn; an L6 block deleted the child's turn from the window of the layer whose job is patterns across turns; and the context was left starting with a scripted reply and no user turn, which Anthropic rejects, for the rest of the session. The prototype keeps them apart (`S.recentKid` at `chittu-v3.html:1041`, `S.history` at `:1120`).
  - **A guarded turn and a scripted reply never enter `history`.** `reply()`'s `intoModelContext` defaults to FALSE so a guard path added later leaks nothing by forgetting; only the successful sandbox path passes true. `addChittu` in the prototype renders and returns — it never appends.
  - **The classifier DOES see guarded turns, deliberately.** Its window exists for "escalating secrecy, boundary-testing, repeated distress", and the guarded turns are the boundary-testing. Blinding it is not the fix.
- **The pipeline's `recentKid` ALREADY ends with the child's turn.** `runTurn` appends before calling any port, so `classify()` must not append `text` again — that put the current turn in the three-turn window twice. `generate()` likewise gets a context already ending with the turn. Both append only when what they were given does not already end with it. The prototype pushes once (`chittu-v3.html:1033`); match it.
- **Prompts are safety logic.** The fifteen hard rules (`@chittu/pedagogy/sandbox-prompt.ts`) and the classifier prompt (`@chittu/safety-kernel/classifier.ts`) are ported verbatim in substance; tests assert each clause still appears, because a deleted prompt line looks like nothing in a diff.
- **The abstractor is the only thing allowed to turn a child's turn into stored text, and the k-floor is the only thing allowed to make a shape readable.** `abstractShape` (`@chittu/safety-kernel`) emits ONLY closed-vocabulary words and six placeholders — `<NAME> <PLACE> <PET> <NUM> <EMOTION> <OOV>` — and `signal_counter.shape` is **NULL until 25 distinct sessions** have produced it. Below the floor the database holds a keyed hash and an integer, so there is nothing to render, redact or leak. Adding a word to `vocabulary.ts` is a privacy decision: every word in there is a word that can survive into the store.
- **The schema's GRANT block is a SPECIFICATION, not an enforcement.** Every environment connects as the table owner; `chittu_app` and `chittu_ops` are NOLOGIN, and `FORCE ROW LEVEL SECURITY` is set nowhere — so the grants and the five RLS policies are inert, and the runtime can write the training corpus today. What actually scopes a child query is `assert_child_scope()`, which RAISES. Keep the specification correct anyway (it is what a deployment switches on), and never describe it as a control that is protecting anybody. PORT-REVIEW, "OPEN — the role separation is declarative".
- **`/ops/signals` ranks by `sightings`, never `k_sessions`** — the session count freezes at 25 the moment a shape is stored, so a queue ordered by it is ordered by a constant. And it renders **nothing** about a sub-floor row, not even redacted: at k=1 the facets and `first_seen_at` are one child's turn, timestamped. No search box either — the console holds the index key, so lookup-by-shape would be a k-anonymity oracle.
- **The runtime writes `signal_counter`. It does not write `training_signal`** — `chittu_app` is granted nothing on the training corpus and that absence is the control. Promotion needs a `failure_class`, which is a judgement about what SHOULD have happened, so it belongs to a named person (`signalRepo.promote`, whose surface is phase 4).
- **The ID-check verdict comes from the vendor, never from the browser.** `automated_id_check` (Didit) hands the parent to a hosted capture page and then asks Didit's API, over this server's own connection, what happened. The client sends ONE thing to `POST /v1/consent/verify-id` — the name printed on the document — and a name decides nothing on its own. Three facts must all hold: status is exactly `Approved`, the holder is 18+, and the name matches. An unrecognised status string is refused, never treated as approval — same rule as `parseClassifier`.
  - **`client.ts` is the PII firewall and the narrowing is the control.** Didit's decision carries `full_name`, `date_of_birth`, `document_number`, `mrz`, `nationality`, `address`, images and biometric scores; `fetchDecision` returns a status, a boolean and a name, and the raw object never leaves the module. `isAdult` is computed INSIDE that module so a DOB cannot reach the adapter even by accident, and the image URLs are never fetched. Widening the returned shape is a privacy decision, not a refactor.
  - **The firewall has a VENDOR-SIDE half, and it lives in a console, not in this repo.** The Didit workflow's *Returned data* list is narrowed to TWO of its thirty-five fields — `full_name` and `age` — so document number, DOB, nationality, address, MRZ, all four quality scores and **all five media assets (document image, document video, portrait, silent selfie, extra files)** are never sent at all. `client.ts` refuses to read them; the workflow refuses to send them. Widening that list in the console silently removes half the control with no diff to review, so treat it as part of this file. Age restrictions are ON at 18 with action DECLINE, which is a second, independent adult check beside `derivedIsAdult`. Narrowing it too FAR is handled too: a decision with no name at all fails as `no_name_returned`, terminal and without burning a parent's attempt, because that is our misconfiguration and not their typo.
  - **The name is compared and discarded — never stored, never hashed.** `hashEvidence` takes the session id, the status, the workflow and two booleans. A stored hash of a name is a guessing oracle over a small, predictable space; that is why it is absent, and a test asserts two different matching names produce the SAME hash.
  - **`vendor_data` carries the challenge id and nothing else.** It is our string inside a third party and it comes back in webhook payloads, so a parent's email or a child's name there is a quiet export of exactly what this product exists not to export.
  - **The `chittu_idcheck` cookie is `sameSite: 'lax'` and the other two are `strict`. Do not "fix" it.** The parent returns from the vendor by a cross-site top-level navigation, and a Strict cookie is not sent on one — with Strict, the cookie is invisible on the single request it exists for. It is affordable because that cookie names a pending verification and cannot approve one.
  - **Name matching is structural, not fuzzy, because Chittu launches in India.** `R. Karthik` and `Karthik R` must both match `KARTHIK RAJENDRAN` — the initial is the father's name, not a middle name. The rule is an order-insensitive token subset with initial expansion, plus a guard that at least one match be between two FULL words, without which a single letter becomes a wildcard. `md` is NOT stripped as an honorific: in South Asia it is Mohammad. A tuned similarity threshold was rejected as indefensible on a legal gate — transliteration variance is absorbed by a bounded retry (3, counted in `consent_record.verify_attempts`, server-side) and then the human rail.
- Parent flags store category only — never a child's quoted words. The dashboard payload is asserted against this: a test sends a distinctive sentence and greps the whole response for it.
- **A layer that reports it ran when nothing ran is worse than a missing layer.** `walk.layers.push('CORPUS')` sat next to a bare `detectSubject()` call for the whole life of the port: every trace in the system claimed a corpus lookup, none happened, and rule 11 of the fifteen hard rules ("If GROUNDED KNOWLEDGE is provided, answer FROM it") had `grounding: null` hardcoded under it. **A prompt clause with nothing behind it is the most expensive kind of safety text there is, because it reads as a working control in review.** Layer 6 now retrieves, and the stamp is conditional on retrieval having actually run.
  - **Layer 6 has FOUR outcomes and collapsing any two is the bug.** `hit` → `· GROUNDED CORPUS` (the prototype's exact string, chittu-v3.html:1142); `miss` → `· CORPUS MISS`; `unavailable` → `· CORPUS UNAVAILABLE`; `off` (no port wired) → **no CORPUS layer in the walk at all**. A miss is a fact about the corpus, `unavailable` is a fact about the deployment, and a caught-and-nulled failure would arrive as a miss — claiming the corpus was consulted when it was not. `ground()` therefore THROWS on failure rather than returning null, exactly as `classify` does for FAST-PATH-ONLY.
  - **Only `published` is ever retrieved, and `retired_at IS NULL` with it.** The CHECK (`published_must_be_signed`) is half the rule; the query is the half that runs. `draft()` has no argument that could publish — promotion is `sign()`, which needs a name, for the same reason `signalRepo.promote` is separate from `observe`. Seeding published rows straight from a script is the lie `helplines/cli.ts` refuses to tell ("importing is NOT verifying"); the fifteen seed entries are exempt only because they are verbatim from prototype v3.3 and a named human signs them at import.
  - **Grounding is not a bypass.** A grounded reply still walks L5 → L6, and the escalation tokens still work — a model handed a fact about volcanoes can still emit CRISIS and still lock the chat. Curated truth changes what the model is TOLD, never what happens to what it says.
  - **Retrieval failure must never become silent free generation.** On a miss or an outage `grounding` stays null and rule 11's other half — "a kind 'I don't know' beats a made-up answer" — is what answers the turn.
  - **`corpus/ground.ts` takes the caller's `tx` and there is no overload that omits it.** The turn runs inside `withChild`. This is quieter than the cases that produced the rule: the corpus is not child data, so `assert_child_scope()` never RAISEs and a `pool` read simply runs outside the transaction while every test stays green.
  - **It does NOT narrow by subject, deliberately.** `retrieve` can and the repo test proves it does; the pipeline passes null. `detectSubject` returns null often (there is no `maths` subject — arithmetic never reaches a model), so narrowing would let a MISDETECTION silently remove a correct fact, and the trace would read as an ordinary CORPUS MISS. Turning it on needs a test proving a misdetected subject cannot hide a hit.
  - **Embedding goes THROUGH THE ROUTER, because embedding a child's turn shows a provider that child's words.** That is the call `provider_clearance` governs, and for one commit it did not: `corpus/embed.ts` held a direct `fetch` to `CHITTU_LOCAL_BASE_URL`, so every embedding bypassed clearance AND metering while `local.ts`'s header claimed "provider_clearance still has to clear it". `router.embed()` now routes, clears, refuses and meters it exactly like a sandbox call.
  - **`DEFAULT_CELLS.embedding` names `local`/`mxbai-embed-large`, and it cannot name Anthropic.** It used to be `{ provider: 'anthropic', model: 'claude-sonnet-5', promptVersion: 'embedding-v0' }` — dead config that read as working configuration, because Anthropic ships no embeddings API. Nothing refused it either: `main.ts`'s reachability check asks whether an ADAPTER exists, and Anthropic's does; what it could not do was embed. **`ProviderAdapter.embed` is optional and `router.embed()` refuses a provider that lacks it — a capability is not something a cell assignment can confer.** Reverting to that config now fails 7 tests.
  - **An embedding is not a completion, so it is a separate adapter method.** No system prompt, no message list, no `maxTokens`, and the reply is a vector. Folding it into `complete()` would mean a `ModelReply` whose `text` is a serialised array. It also does not retry where `complete` does: a dropped sandbox call costs a child their answer, a dropped embedding costs the GROUNDING on an answer they still get.
  - **`embedding` is EXCLUDED from `main.ts`'s boot-time reachability refusal, and that exclusion is load-bearing.** Every other category is required to serve a child at all; the corpus is an enrichment. Including it would refuse to start every Anthropic-only deployment, which is all of them. The absence is not silent — no grounding port is wired, no CORPUS layer is stamped, and the boot banner says `grounded corpus: OFF` with the routing reason.
  - **A refused route reaches the pipeline as CORPUS UNAVAILABLE, never as a miss.** "Not cleared in this market" and "the corpus has nothing on volcanoes" are different facts and only one is a reason to write more corpus.
  - Every hosted alternative to the self-hosted embedder is a new counterparty for children's text: a `provider_clearance` row and a Council decision, not an import.
  - **The dimension guard cannot catch the failure that matters, so the model name is pinned in the seed provenance.** A 768- or 384-d model fails loudly on the column type. A DIFFERENT 1024-d model fails nowhere: right width, query runs, three nearest chunks returned from a space unrelated to the one the corpus lives in — confident nonsense under a heading that says "verified". Re-embed everything if the model changes.
- **The teen carve-out is enforced in THREE places, and it was two for months while a third undid them.** The schema's `teen_bodies_are_never_stored` CHECK; the transcript route, which decides from `session.band` where the CHECK looks at `message.band`; and `writeRuntime` in `apps/api/src/store.ts`, which writes `history` and `recentKid` EMPTY for a `thinker`. That last one is the fix: the blob carried the child's own sentences and round-tripped them, so the ruling held on `message` and was defeated in the same transaction. **The cost is real and was chosen: a teen's classifier window is one turn and their conversation carries no context between requests.** Abstraction is not a way out — `abstractShape` destroys distinctive tokens, not meaning, and "i cut myself last night" survives it verbatim.
  - **Anything new in `runtime_enc` must be argued for.** `teen-carveout.test.ts` asserts the blob's whole key set, so a field arriving without anyone asking what it carries fails there — which is exactly how `history` got in.
- No engagement mechanics anywhere, including prompts: no streaks, guilt, "don't go" language, or attachment simulation.
- Consent before existence: no code path may reach the chat before the consent ledger exists.
- **`POST /v1/session` resumes, it does not always create.** `crisis_lock` is per-session, so always opening a new one made a page reload an escape from it. A locked session is resumed regardless of age; the client takes `crisisLock` from that response, never from local state. The 12-hour staleness window (`SESSION_STALE_AFTER_HOURS`) is a signed-off product decision with a value pin in the tests — move it deliberately.
- **Destructive actions require a live parent session** (`apps/api/src/cookies.ts`): erasing an account and lifting a crisis lock both need the `chittu_parent` cookie, which only a correct PIN mints and which lasts 15 minutes. Never add a destructive route that trusts a consent cookie alone — a child holds one of those.
- Credentials travel in httpOnly cookies, never in a response body, a URL, or `localStorage`. `POST /v1/session` has no body fallback on purpose.
- **The key-provider guard is an ALLOWLIST, and `deploymentEnv` is the only thing allowed to map `NODE_ENV`.** `localKeyProvider` refuses unless the env is exactly `'dev'`. It used to refuse only `'prod'` while the Dockerfile sets `NODE_ENV=production` — two strings that are not equal — so the guard never fired: every task would have booted with an ephemeral `randomBytes(32)` master key, different per task and discarded on restart, taking parent email, child first name, message bodies, memory facts AND the email blind index with it. The bug was not the mismatch; it was that an unrecognised value defaulted to *permitted*. Same rule as `parseClassifier`: never invent a safe answer for input you do not fully recognise.
- **Key resolution lives in `apps/api/src/keys/`, NOT in `bootstrapDb`.** `providers/cli.ts` and `helplines/cli.ts` call `bootstrapDb()` and use only `{ pool }`. Building keys inside it makes the fail-closed guard take down the **helpline sweep** — the GAP-06 P0 path — over a key it never touches. `main.ts` calls `resolveKeys()` above `bootstrapDb()` so config refusals are not shadowed by a connection error.
- **The blind-index key is supplied, never generated.** `indexKey()` must return the same bytes in every task forever or `parent.email_hash` stops matching and a parent cannot be found by email. KMS has no "same bytes twice" call, so it comes from Secrets Manager (`CHITTU_INDEX_KEY`, base64, 32 bytes) and `resolveKeys` refuses a CMK without one. It is created by hand — generating it in Terraform would put a value that reverses every family's email hash into the state file.

## Known gotchas (regression-locked — tests must cover these)

- Subject detection order: languages BEFORE science ("how do you say…" must not match science's `how do`).
- `[STEPS]` block delimiter is `|`; the maths pictorial emoji-group separator is `·`. Do not swap — they collided once and truncated lessons.
- Audit chain writes are serialized (`auditQueue`) so the hash chain can never fork.

## When building the backend (Phase 1)

- TypeScript + Fastify, Postgres (+pgvector), modular monolith. Provider calls go behind one router interface (`route(category) → {provider, model, promptVersion}`).
- **There are two providers**: `anthropic` and `local` (an OpenAI-compatible endpoint — Ollama, `mlx_lm.server`, vLLM — set `CHITTU_LOCAL_BASE_URL`). The second exists to TEST the provider-agnostic claim, and it does because the wire genuinely differs: `/chat/completions`, the system prompt folded into `messages[0]`, `choices[0].message.content`. Sending Anthropic's shape to it produces a model that never saw its own prompt — no error, just a model ignoring the fifteen hard rules. **Google is ruled out by its own terms** for the Developer API; Vertex is a different contract and unresolved (model-plan §5 decision 5).
- The client must become thin: all guards server-side; browser only renders blocks/chips and does TTS.
- Port the 246-assertion Playwright suite into API-level contract tests; the red-team corpus is a CI release gate (zero criticals to ship).
